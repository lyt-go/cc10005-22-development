# 多源异构数据接入引擎

面向多源异构数据接入、智能代理调度、动态限速、爬虫深度管理、数据去噪、格式转换与采集质量监控的数据接入工程管理平台。

这是一个前后端分离的管理平台：前端 React + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 React + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   ├── app/mapping_seed.py   映射预览的解析路径、映射表与样例批次定义
│   ├── app/store.py          内存数据仓库与示例数据
│   └── tests/                后端回归测试（python -m unittest discover -s tests）
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。

## 字段映射冲突判定与转换预览

页面入口：前端导航「映射预览」（`/mapping`），后端接口前缀 `/api/mapping`。

选择解析模板（PARS-0002）、转换器（FORM-0002 / FORM-0003）、字段映射表和样例批次后，
预览会逐字段给出：最终值、采用来源、被覆盖 / 空值跳过的来源、冲突列表和冲突结论；
日期模板、数值精度、空值占位符的每次覆盖都列出来源链。预览只读，不写入正式分发文件。

判定口径（实现细节）：

1. 同一输出字段的多条映射行按优先级从高到低裁决，优先级相同按行号（行号小者优先）。
2. 日期模板、数值精度、空值占位符按「映射行显式值 → 转换器默认 → 解析模板默认 → 系统默认」逐字段解析；
   不适用的维度（如字符串字段的日期模板）只登记候选，不参与输出。
3. 空值默认不覆盖已有值；映射行显式开启「允许空值覆盖」时才参与竞争，并在结论里标为「空值覆盖」。
4. 转换器空值策略为「保留空值」时，优先于解析模板默认占位符，输出保持为空。
5. 空值占位符只填充最终值，不参与输出字段重命名。
6. 未被冲突波及的输出字段照常保留；标记为不分发的字段只参与预览核对，不写入输出格式。

接口：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/mapping/options` | 解析模板、转换器、映射表、样例批次与规则 |
| POST | `/api/mapping/preview` | 生成预览（空数据 / 类型异常 / 中断都在结果里说明） |
| POST | `/api/mapping/previews/{id}/retry` | 仅解析中断的预览可重试，返回恢复原因 |
| POST | `/api/mapping/previews/{id}/confirm` | 核对冲突后确认，生成一份转换结果草稿 |
| GET | `/api/mapping/results` | 转换结果清单，历史版本单独列出 |

约束：

- 有冲突的预览必须勾选「已核对冲突」才能确认；类型转换阻断的预览不能确认。
- 确认只生成转换结果草稿，不写正式分发文件；同一输入重复确认复用已有结果，只保留一份。
- `formatter` 的「启用转换器」动作要求该转换器已有确认过的预览，否则被拦下并说明原因。
- 历史输出（CONV-0001 / CONV-0002）按生成时的格式（NDJSON / CSV、当时的日期模板和精度）固化，
  当前转换器配置变化不会改写历史结果。

样例批次用于覆盖空数据、边界输入和异常场景：

| 批次 | 用途 |
| --- | --- |
| `BATCH-NORMAL` | 正常数据，含多路径冲突、空值与日期/精度覆盖 |
| `BATCH-EMPTY` | 空数据，预览展示空态且不允许确认 |
| `BATCH-BOUNDARY` | 空白标题、0.005 舍入、最大日期、全零条码、零库存 |
| `BATCH-INVALID` | 价格 / 库存 / 日期类型异常，预览阻断确认 |
| `BATCH-TRANSIENT` | 首次解析超时，重试后恢复并说明中断原因 |

核对样例：PARS-0002 + FORM-0002 + MAP-0002 覆盖字段映射结果与类型转换结果；
PARS-0002 + FORM-0003 + MAP-0003 覆盖空值覆盖、CSV 输出与历史版本保留。
